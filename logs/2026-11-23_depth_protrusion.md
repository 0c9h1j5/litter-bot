# 2026-11-23 깊이 렌더로 '바닥 위 돌출물' 찾기 — 가능성 확인 (시뮬)

질문: 생수병은 투명해서 색(HSV) 인식이 실패할 수 있다. MuJoCo에서 깊이 이미지를 렌더해 '평평한 바닥 위로 솟은 것'을 찾을 수 있나?

- 환경: MuJoCo 4.0.1, macOS(Apple M4), `mujoco.Renderer` 640 × 480, `enable_depth_rendering()`
- 장면: `scenes/gym_v0.xml`을 복사해 `litter_bottle1`만 **반투명(rgba 알파 0.25)**으로 바꾼 것
- 카메라: Stretch 머리 카메라 대역(자유 카메라). 높이 약 1.3 m, 코트 쪽에서 벤치 쪽을 42° 내려다봄 (Stretch 실제 머리 카메라 자세는 4일차에 모델 카메라로 다시 한다)
- 방법: 깊이 → 월드 좌표로 바꾸고, **높이 3 cm 넘는 픽셀**을 덩어리로 묶는다. 덩어리 꼭대기가 **0.30 m 미만이면 '쓰레기 후보', 이상이면 '장애물'**(벤치 다리·의자)로 나눈다.

| 결과 | 값 |
| --- | --- |
| 경고 | macOS에서 `ARB_clip_control unavailable ... depth accuracy will be limited` — 이 컴퓨터의 깊이 정밀도가 제한된다. 2~3 m 거리에서 cm 단위 돌출 검출에는 문제없었지만, 다른 PC(Linux·EGL)에서 다시 확인한다 |
| 렌더 시간 (RGB + 깊이 1장) | 18~144 ms (첫 장이 느림) |
| 화면 안 쓰레기 | 5개 (바닥: 반투명 생수병, 생수병, 벤치 아래 캔, 벤치 다리 옆 컵 / 벤치 위: 생수병) |
| 찾은 쓰레기 후보 | **3개** — 반투명 생수병 (0.10, 0.78), 생수병 (0.89, 0.76), 벤치 아래 캔 (1.29, 1.08). 위치 오차 약 2 cm 이내 |
| 놓친 것 | 2개 — 벤치 다리 옆 컵과 벤치 위 생수병이 벤치와 한 덩어리('장애물', 꼭대기 0.66 m = 벤치 위 병의 꼭대기)로 묶였다 |
| 잘못 찾은 것 | 0 (벤치 덩어리는 꼭대기 0.66 m라 장애물로 분류) |

그림: `docs/img/depth_test.png` (왼쪽 RGB, 가운데 깊이, 오른쪽 '높이 3 cm 이상' 마스크)

**해석**
1. **시뮬 깊이 렌더는 된다.** 투명도와 상관없이 형상이 깊이에 그대로 찍힌다. 즉 시뮬에서는 투명 병이 깊이로 '보인다'.
2. 그러나 **이것은 시뮬이 낙관적인 부분이다.** 실제 깊이 카메라(Stretch 3 머리의 스테레오 깊이 카메라 등)는 투명·반사 물체에서 깊이가 비거나 틀리는 경우가 많다고 알려져 있다(가정 — 출처 확인 필요). 그래서 실물·현장에서는 **뚜껑·라벨 색 + 깊이 돌출**을 함께 쓴다.
3. RGB 화면에서 반투명 병은 마루색과 섞여 보인다(눈으로 확인). 채도 기준 HSV로는 놓치기 쉽다.
4. 벽·벤치·사람 다리 옆에 붙은 쓰레기와 **벤치 위·창문틀 위 쓰레기**는 '바닥 기준'으로는 못 찾는다 → **받침면(바닥 0 m, 벤치 윗면 0.45 m, 창문틀 윗면 1.0 m)을 지도에 넣고 각 받침면 위 돌출**을 보며, 고정물 지도(벤치·벽)를 빼는 규칙이 필요하다(3주차, 기획안 6-7).
5. 크기 규칙만으로는 **농구공(지름 약 24 cm)·가방·신발**도 '0.30 m 미만 돌출'에 걸린다. 그래서 쓰레기 후보는 **원기둥 모양(위에서 본 지름 5~10 cm, 높이 6~25 cm)**일 때만 인정하고, 공(구)·넓은 덩어리(가방)·납작하고 긴 것(신발)은 '장애물'로 둔다(기획안 6-7).

재현: `uv run --with pillow --with scipy python src/checks/depth_bumps.py <장면.xml> <출력.png>` (반투명 병 장면은 gym_v0.xml의 litter_bottle1 rgba를 ".9 .95 1 .25"로 바꿔 만든다)
