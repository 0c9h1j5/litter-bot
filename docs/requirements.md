**용어** (이 문서에서 처음 나오기 전에 한 줄씩)
- **핫스폿** = 쓰레기가 자주 모이는 자리 (벤치 구역·코트 구석. 창문틀은 SO-101 손끝 최고 0.67 m라 빠짐).
- **핫스폿 순회 (모드 1, 보조)** = 그 자리들만 정해진 순서로 돌며 병·봉지를 집기.
- **직선 훑기 (모드 2, 주)** = 코트를 나란한 줄로 왕복하며 바닥을 밀고 닦기. 줄 끝에서만 방향을 바꾼다.
- **전체 모드 (주 운영)** = 사람 없는 빈 시간(첫 대관 전·마지막 대관 후·대관이 비는 시간)에 하는 정리: 핫스폿 순회(집기) + 장면 전체 밀기 + 충전 자리 복귀. 상용 청소 로봇과 같은 운영 방식.
- **벤치만 줍기 (선택, 버튼)** = 관리자가 버튼으로 시키는 '벤치 구역 쓰레기만 줍기' (Should, R-32). ~~짧은 모드(대관 사이 정리)~~는 v0.5에서 없앰.
- **벤치 앞 띠** = 선수 벤치 앞 사이드라인 쪽의 긴 바닥 띠 (시뮬 4.5 m × 0.8 m).
- **집게 대상** = 집게로 줍는 쓰레기: 생수병·캔·컵·구겨진 과자 봉지. 수거율 = 집게 대상 중 통(팔 옆에 거는 통)에 넣은 비율.
- **커버리지** = 구역을 작은 칸(시뮬 5 cm, 실물 10 cm)으로 나눴을 때 패드가 한 번 이상 지나간 칸의 비율.
- **모듈 A** = 청소 모듈: 앞 모서리 옆솔 2개(안쪽으로 돌며 가운데로 모음 — 실물은 V자 사선 가이드로 시작) → 흡입(차체 밑 가운데, 앞바퀴 뒤) → 뒤 회전 패드(마른 극세사 패드 2개가 돌며 닦음).
- **분실물** = 기획자가 있을 수 있는 물건 (옷·수건·물이 남은 병·개인 물건). 줍지 않고 사진·위치만 알린다. 소지품 = 공·가방·신발 (장애물로 본다).
- **모음 자리** = 줄 끝에 납작한 큰 봉지를 밀어 모아 두는 자리 (사람이 한 번에 줍는다).
- **받침면 · 깊이 돌출** = 물건이 놓인 면(바닥·벤치 윗면)과, 깊이 카메라로 본 그 면보다 솟은 부분.
- **참값** = 시뮬레이터가 알려 주는 정답 위치. 3주차부터는 쓰지 않고 카메라로만 찾는다.
- **사람 대역** = 시뮬에서 사람 대신 움직이는 기둥. 시드 = 쓰레기 배치를 무작위로 바꾸는 번호 (10개 = 10판).
- **판정 함수** = 시뮬 한 판의 결과를 받아 성공(True)/실패(False)를 내는 함수 (`src/judge.py`).

## ① 요구사항 나누기

사용자의 말 → 로봇 전체 → 기능별 숫자로 나눈다. **전체 모드**(빈 시간, 주 판정)를 기준으로 쓴다. 아래 칸의 시간을 더하면 위 칸의 예상 시간이 되고, 기준과의 차이가 여유다. 괄호 안 C-xx는 계산 줄(①-1, 새 값은 ①-2)이다. 시간은 운행 속도 0.3 m/s 기준이다 (기획자 결정 2026-11-24 — 상용 휠리 J30 최고 속도 0.3 m/s와 같음, 사람 정지 여유 · ①-2 C-22·C-23). 차체는 넓은 차체(390 × 280 mm, 패드 폭 0.28 m 가정)로 바뀌었지만 아래 칸의 시간은 v0.5 X3 차체(패드 0.20 m) 계산을 그대로 둔다 — 넓은 차체 값은 ①-2의 'wide @0.3 m/s' 열(전체 약 400 s).

로봇 한 판을 0~8단계로 쪼갠다. **6단계(장애물·사람)는 1~5단계 이동 중 내내 겹쳐 돈다.** 전체 모드는 0~8단계를 모두 하고(5단계 = 장면 전체), '벤치만 줍기'(R-32)는 2단계에서 벤치 구역만 가고 5단계를 건너뛴다. 센서는 시뮬(MuJoCo robot_v2 — 메카넘 + SO-101) / 실물(메카넘 축소판)로 나눠 적는다. 숫자 뒤 C-xx는 ①-1 계산 줄이다.

```
0 대기·시작 → 1 출발·위치 확인 → 2 핫스폿 이동 → 3 인식 → 4 집기·담기 ─┐
                                    ▲ (다음 핫스폿)            │
                                    └──────────────────────────┘
          → 5 직선 훑기 → 8 끝·결과 보고
   (1~5 내내) 6 장애물 우회·사람 멈춤/재개   (3·5에서 분실물을 보면) 7 분실물 사진·알림
```

## 판정 함수 (src/judge.py)

교안 원칙대로 **테스트는 사람이 쓰고(`tests/test_judge.py`), 판정 함수 구현은 에이전트에게 맡긴다.** v0.6에서 테스트를 새로 썼고(사람 몫), v0.7에서 `src/judge.py`를 테스트를 고치지 않고 구현했다 — `uv run pytest -q tests` = 29 passed. 비율은 정수 곱(10회 평균은 분수 `Fraction`)으로 비교한다.

- `judge_full_mode(result: dict) -> bool` — 전체 모드 한 판. R-04(수거율 80%) · R-06(장면 커버리지 95%, 분모 = `grid_cells − obstacle_cells`) · R-18(`elapsed_s ≤ FULL_MAX_S` 650 s, `dock_dist_m ≤ DOCK_RADIUS_M` 0.1 m) · R-26(모드 1 480 s, 모드 2 600 s) + 안전 R-09·16·24 + 분실물 R-10·11·17을 모두 지키면 True.
- `judge_bench_only(result: dict) -> bool` — 관리자 버튼 '벤치만 줍기'(R-32). 수거율 80%(5개 중 4개) + 충전 자리 복귀 + 같은 안전·분실물 조건. 시간·커버리지는 보지 않는다.
- `judge_ten_runs(results: list[dict]) -> bool` — 10회 집계(T-21). 수거율은 회별 비율의 평균 80% 이상 + 최저 회 60% 이상, 나머지는 10회 모두 한 판 기준. 10개가 아니면 `ValueError`.
- `decide_start(time_to_next_booking_s, people_on_court, bench_button=False) -> str` — 출발 판단(T-22, R-25·R-01·R-32). 사람 있음 → `"none"`, 버튼 → `"bench_only"`, 남은 시간 ≥ 650 s → `"full"`, 아니면 `"none"`. 하던 줄을 멈추고 복귀하는 문턱은 숫자가 정해지지 않아 넣지 않았다 (확인 필요).
- 지운 것: `judge_short_mode`, `SHORT_MAX_S = 360.0` (T-34가 없어졌는지 확인).
- 입력 `result` = 시뮬 1회 결과 dict (키와 단위는 `src/judge.py` docstring). v0.5에서 바뀐 키: `coverage_pct`(%) → `grid_cells`·`obstacle_cells`·`covered_cells`(칸 수, 정수 비교), 새 `dock_dist_m`, `elapsed_s`는 전체 모드(복귀까지) 시간.
- 장면 설정 오류(`targets ≤ 0`, 칠할 칸 0칸, 10회가 아님)는 `ValueError` — 성공·실패 판정을 하지 않는다.
